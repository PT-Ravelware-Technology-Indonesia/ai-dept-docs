## Project Overview
Sistem edge computing yang berjalan on premises untuk di gunakan di sorting Si-Cepat. Tugasnya adalah mengukur dimensi dan berat secara otomatis, lalu mengirimkan hasilnya ke backend melalui RestAPI (FastAPI) dan MQTT.

## Konteks Penggunaan
Sistem dipasang conveyor belt. dengan alur scan barcode → Timbang Berat → Hitung Dimensi → Kirim hasilnya melalui MQTT

Di site, Operator 1 men-scan paket dengan scanner handheld di hulu conveyor, lalu Operator 2 memindahkan paket ke timbangan di stasiun DWS. Karena barcode masuk lebih dulu, barcode disimpan di antrian FIFO dan dipasangkan dengan paket di timbangan berdasarkan urutan.

# FITUR

## Pengukuran Dimensi Otomatis
Kamera depth Orbbec dipasang diatas platform timbangan menghadap kebawah. Setiap frame, sistem melakukan segmentasi depth untuk mendeteksi objek yang ada di bawah kamera. Jika objek menutupi atau bersinggunakn dengan titik tengah frame, sistemn akan mulai mengukur dimensinya dan merata-ratakan hasilnya dari beberapa frame sebelumnya.

- Menggunakan Hardware D2C (Depth to Color Alignment)
- Nilai Intrinsik kamera dobaca otomatis dari SDK saat Startup
- Lantai dimodelkan sebagai bidang 3D (RANSAC) dan dikalibrasi otomatis — lihat [Kalibrasi Titik Nol Lantai](#kalibrasi-titik-nol-lantai)
- Tinggi diukur dari point cloud: piksel objek di-deproject ke 3D, tinggi = jarak titik ke bidang lantai
- Panjang & lebar dihitung di ruang metrik (mm), bukan piksel, sehingga bebas distorsi perspektif
- **Edge-aware refinement**: piksel di tepi transisi depth (antara objek & lantai) yang depth-nya tidak reliabel dibuang menggunakan Sobel gradient, agar contour tidak melebar dan L/W tidak over-estimate. Dikontrol oleh `edge_gradient_threshold` (mm/px, 0 = nonaktif).

### Measurement Profile
Cara mengukur L/W dan tinggi dipilih lewat satu nilai `measurement_profile`. Satu profil membundel beberapa knob geometri (termasuk `edge_gradient_threshold`), jadi A/B dan rollback cukup ganti satu nilai lewat `PUT /config`. Knob milik profil hanya bisa diubah manual kalau profilnya `custom`.

| Profil | L/W | Catatan |
| --- | --- | --- |
| `topface_legacy` (default) | Siluet diproyeksikan ke bidang permukaan atas paket | Perilaku produksi awal. Eksak untuk kotak |
| `exp2_pointcloud` | Tiap piksel siluet memakai depth aslinya (point cloud) | Bagian paket yang menggembung ikut terukur. Ditune bersama filter depth |
| `custom` | Diatur manual | Untuk tuning |

#### Cara Kerja Panjang/Lebar dengan Point Cloud
Tinggi (H) dihitung lebih dulu, lalu L/W dihitung dari "jejak" paket di bidang lantai:

1. **Siluet.** Piksel yang depth-nya lebih dekat dari bidang lantai dikurangi `min_height_thresh` dianggap bagian paket. Untuk L/W dipakai siluet mentah, sebelum edge filter dan erosi yang menyusutkan tepi, dibatasi ke sekitar kontur objek (kontur di-dilate `fp_dilate` piksel) dan dibersihkan dari bintik noise.
2. **Deproject ke 3D.** Tiap piksel siluet diubah menjadi titik 3D (mm) memakai **depth aslinya** dan intrinsik kamera: `X = (u − cx) · Z / fx`, `Y = (v − cy) · Z / fy`. Karena tiap titik memakai jaraknya sendiri ke kamera, bagian paket yang lebih rendah (lebih jauh dari kamera) dihitung dengan skala yang benar.
3. **Saring titik.** Hanya titik dengan tinggi di atas lantai antara `min_height_thresh` dan `H + top_face_band_mm` yang dipakai, sehingga titik lantai di tepi paket dan spike di atas paket terbuang.
4. **Proyeksi ke lantai.** Titik 3D diproyeksikan ke koordinat 2D (mm) di bidang lantai, seperti melihat paket tegak lurus dari atas lantai, terlepas dari kemiringan kamera.
5. **Orientasi.** `minAreaRect` atas titik 2D menentukan arah sumbu panjang paket, lalu semua titik diputar mengikuti arah itu.
6. **Ekstent.** Panjang dan lebar = rentang titik di dua sumbu tersebut, diambil dari persentil `trim_low` sampai `trim_high` untuk membuang segelintir titik outlier. L = sisi terpanjang, W = sisi terpendek.
7. **Stabilisasi & koreksi.** Hasil beberapa frame dirata-rata, dikoreksi regresi kalibrasi per sisi, lalu dikonversi ke cm.

Bedanya dengan `topface` hanya di langkah 2 dan 3: `topface` tidak memakai depth asli, melainkan menganggap semua piksel siluet berada di ketinggian permukaan atas (H). Untuk kotak hasilnya sama persis, tapi bagian paket yang menggembung di bawah permukaan atas ikut dihitung seolah setinggi permukaan atas, sehingga terbaca lebih kecil.

### Filter Depth (Opsional)
Rantai filter SDK Orbbec (spatial, noise removal, temporal, hole filling) bisa dinyalakan dengan `depth_filter_enabled`. Filter dipasang tepat setelah frame diambil, sehingga fit bidang lantai dan pengukuran melihat depth yang sama. Default **mati**.

## Kalibrasi Titik Nol Lantai
Titik nol = bidang lantai yang menjadi acuan semua pengukuran tinggi. Kalibrasi berjalan otomatis saat aplikasi start dan setiap kamera di-restart (otomatis maupun via `POST /restart`). Selama kalibrasi, pengukuran di-pause dan **area ukur harus kosong**.

- Hasil fit dibandingkan dengan nilai titik nol terakhir yang valid. Menyimpang lebih dari 50 mm → ditolak dan diulang (maks 3 kali), karena kemungkinan ada barang di area ukur.
- Kalau beberapa hasil yang ditolak saling konsisten dan lebih jauh dari kamera (mis. kamera dipindah), nilai lama dianggap basi dan diganti otomatis.
- Kalibrasi yang gagal **tidak menimpa** nilai lama; sistem tetap jalan dengan titik nol lama.
- Saat platform kosong, bidang lantai di-fit ulang tiap 180 detik untuk mengompensasi drift sensor, sekaligus memulihkan status `DEGRADED` tanpa restart.

Status dikirim ke topic `DWS-SICEPAT/NOTIFICATION` untuk ditampilkan ke operator:

| Status | Arti | Yang perlu dilakukan operator |
| --- | --- | --- |
| `CALIBRATING` | Kalibrasi berjalan | Kosongkan area ukur dan tunggu |
| `PLATFORM_OCCUPIED` | Ada barang di area ukur saat kalibrasi | Angkat barang dari timbangan |
| `OK` | Kalibrasi berhasil | Operasi normal |
| `DEGRADED` | Kalibrasi gagal, sistem pakai titik nol lama | Kosongkan platform agar re-fit berkala bisa memulihkan. Kalau tidak pulih, cek kamera dan lapor tim |

## Kamera RGB Sekunder (Foto Bukti Paket)
Selain kamera depth Orbbec, sistem dapat menggunakan **kamera USB webcam tambahan** sebagai sumber foto bukti paket yang lebih jelas. Kamera ini hanya melakukan capture (mengikuti trigger transaksi), bukan untuk pengukuran.

- Berjalan di background thread agar frame terbaru selalu siap saat trigger (tanpa lag warmup).
- **Non-fatal**: jika kamera webcam gagal/ tidak terpasang, sistem tetap jalan dan capture sekunder dilewati.
- Foto hasil webcam (jika tersedia) yang dikirim sebagai `image_base64` di payload `DATA/RESULT` dan disimpan ke folder `captured_images_rgb/`.
- Dapat dinonaktifkan via `RGB_CAMERA_ENABLED=False` di `.env`.

:::info{title="Deteksi Index Kamera"}

Index webcam diatur via `RGB_CAMERA_INDEX`. Jika index salah (mis. ter-claim oleh driver lain seperti RGB internal Orbbec), kamera bisa "terbuka" tapi tidak mengirim frame — sistem mendeteksi ini dalam 3 detik dan melewati capture sekunder. Gunakan `tools/list_cameras.py` untuk mengecek index yang benar.

:::

## Integrasi Timbangan BLE
Berat paket dibaca dari timbangan digital yang terhubung via Bluetooth Low Energy. Sistem otomatis mendeteksi UUID characteristic BLE yang, sehingga tidak perlu konfigurasi UUID manual.

- Auto-reconnect jika BLE terputus sebanyak 3 kali percobaan.
- Deteksi stability flag dari byte terakhir dari notifikasi BLE.
- Berat di-reset ke 0 otomatis ketika BLE disconnect agar tidak terjadi trigger palsu.

## Integrasi Barcode Scanner via TCP
Scanner barcode terhubung ke sistem melalui TCP server yang berjalan di port 9004. Scanner mengirim string barcode setiap kali scan berhasil.

- Barcode Debounce: barcode yang sama tidak diproses ulang dalam interval waktu tertentu.
- Barcode Expired: Barcode yang tidak diikuti berat stabil dalam batas waktu tertentu (dapat di konfigurasi) akan dianggap expired dan direset.

### Barcode HID Listener
Untuk scanner handheld wireless (receiver 2.4G yang hanya punya mode keyboard), scan ditangkap oleh **Barcode HID Listener** lewat low-level keyboard hook Windows, lalu dikirim ke TCP server yang sama sebagai client. Listener berjalan sebagai proses terpisah lewat Task Scheduler, karena keyboard hook butuh sesi desktop. Input touch keyboard Windows tetap diteruskan normal.

:::warning{title="Keyboard Fisik Ikut Terblokir"}

Selama listener jalan, semua keystroke fisik dianggap berasal dari scanner, jadi keyboard USB tidak berfungsi. Untuk maintenance dengan keyboard fisik, hentikan listener dulu.

:::

## Antrian Barcode (FIFO Queue)
Ketika beberapa paket di-scan berturut-turut sebelum transaksi sebelumnya selesai, barcode tambahan **tidak dibuang** melainkan dimasukkan ke antrian FIFO (kapasitas maksimal 10). Setelah satu transaksi selesai dan barang diangkat, barcode berikutnya otomatis ditarik dari antrian.

- Dedup: barcode yang sudah aktif atau sudah ada di antrian tidak ditambahkan dua kali.
- Jika antrian penuh (10), barcode baru di-drop dan sistem mem-publish status `QUEUE_FULL` ke topic `DISPLAY/BARCODE` agar operator tahu.

## Trigger Logic
Transaksi pengukuran hanya dieksekusi ketika tiga kondisi terpenuhi dan bertahan selama `stability_delay` detik:

:::info{title="Kondisi Trigger"}

- Barcode sudah di-scan.
- Berat stabil > 0.02 kg.
- Barang terdeteksi dan bisa diukur (ada di area titik tengah frame).

:::

Ini mencegah pengiriman data saat masih bergerak atau belum ada barcode yang di scan.

:::warning{title="Safety: Tunggu Barang Diangkat"}

Setelah satu transaksi selesai, sistem masuk state **menunggu barang diangkat** (`_awaiting_item_removal`). Trigger berikutnya diblokir sampai berat kembali ≤ 0.02 kg (barang fisik diangkat dari timbangan). Ini mencegah satu paket terukur dua kali. Setelah barang diangkat, barcode berikutnya ditarik dari antrian.

:::

## Kalibrasi Dimensi
Sistem mengoreksi error sistematis pengukuran menggunakan **regresi linear per sisi**. Setiap sisi (panjang/pendek/tinggi) dikoreksi dengan rumus `final = slope × raw + intercept` yang difit ke nilai mentah hasil pengukuran. Operator mengukur beberapa objek referensi yang sudah diketahui ukurannya, dan sistem menghitung parameter regresi optimal dari data tersebut.

### Pengambilan Sampel per Objek
Berbeda dari pengukuran transaksi biasa, kalibrasi mengambil **beberapa sampel manual (N, default 5)** untuk tiap objek referensi. Tiap sampel diambil pada orientasi berbeda (lurus / diagonal kiri / diagonal kanan / dst) dan diperlakukan sebagai satu observasi regresi tersendiri (measured berbeda, actual sama). Ini membuat MAE jujur mencerminkan variasi orientasi dan mencegah fit overfit ke satu posisi.

| Model | Rumus | Catatan |
| --- | --- | --- |
| Linear | `final = slope × raw + intercept` | Model yang dipakai produksi (config). |

:::tip

Gunakan **minimal 2 objek referensi** (`MIN_POINTS`). Direkomendasikan **≥4 objek dengan ukuran bervariasi** — satu kecil (~15cm) dan satu besar (~50cm) — agar slope+intercept ter-fit benar. Dengan hanya 1 ukuran, regresi degrade ke rasio sederhana (intercept=0).

:::

- Capture (`/calibrate/measure`) hanya berhasil jika ada objek terdeteksi di **tengah frame** dan bacaan live masih segar (tidak lebih lama dari 1.5 detik). Jika tidak, sistem menolak dengan error 400.
- Sampel maupun data point bisa dihapus untuk diulang tanpa me-restart sesi — gunakan `DELETE /calibrate/measure/{i}` (hapus 1 sampel di buffer berjalan) atau `DELETE /calibrate/point/{i}` (hapus 1 objek referensi).
- Standardisasi long/short (max/min L,W) konsisten dengan pengukuran — jika input L/W tertukar.
- Riwayat semua sesi kalibrasi (parameter regresi + MAE) disimpan ke `calibration.json`.
- `POST /calibrate/confirm` langsung menerapkan hasil fit ke config (`slope_*`/`intercept_*`) — efektif langsung tanpa restart.

## Live Stream & Developer Mode
Frame hasil pemrosesan di-stream via MJPEG HTTP di endpoint /stream. Dashboard dapat menampilkan preview kamera secara realtime.

- Frame di-resize ke 720x540 sebelum stream untuk efisiensi bandwidth.
- FPS stream di-cap 24fps.
- Dev Mode: Aktifkan dengan `DEV_MODE=true` di `.env` untuk mode debugging.

:::info{title="Dev Mode"}

Saat `DEV_MODE=true`, stream menampilkan grid 2x2 — **RAW**, **DEPTH**, **MASKING**, dan **RESULT** — sehingga memudahkan debugging pipeline pengukuran secara visual.

:::

## Runtime Config via HTTP API
Semua parameter tuning dapat diubah saat runtime melalui PUT /config tanpa perlu restart sistem. Perubahan langsung efektif dan disimpan ke config.json untuk persistensi.

:::note

Perubahan config via API bersifat persisten — nilai tersimpan di `config.json` dan tetap berlaku setelah restart.

:::

## Auto-Restart & Recovery Kamera
Jika kamera depth berhenti mengirim frame (stuck), sistem tidak langsung mati. Setelah mencapai batas kegagalan frame berturut-turut, pipeline kamera di-restart otomatis tanpa mematikan program, lalu kalibrasi titik nol lantai dijalankan ulang.

- Auto-restart dicoba hingga 3 kali. Jika kamera tetap tidak pulih, baru sistem melaporkan error fatal ke MQTT dan exit.
- Counter restart di-reset setelah kamera benar-benar pulih (frame kembali normal).
- Restart juga bisa dipicu manual via endpoint `POST /restart` (mis. dari dashboard) tanpa restart program. Response menunggu kalibrasi lantai selesai.

## Resiliensi MQTT Offline
Jika broker MQTT sedang offline saat sebuah transaksi selesai, hasil pengukuran **tidak hilang**. Payload disimpan sebagai *pending result* dan otomatis dikirim ulang (flush) begitu koneksi MQTT pulih kembali.

- Auto-reconnect ke broker dengan retry tiap 5 detik.
- LWT (Last Will and Testament): jika sistem mati mendadak, broker otomatis mem-publish status `OFFLINE` ke topic `STATUS`.

## Transaction Profiler
Untuk analisis performa, setiap transaksi dapat di-profil: waktu tiap tahap lifecycle (barcode diterima → berat stabil → trigger → publish MQTT) dicatat ke file CSV (`transaction_logs/transactions.csv`).

- Mencatat durasi tahapan kunci: waktu pergerakan barang, hold delay aktual, durasi proses, durasi publish MQTT, dan total durasi.
- Diaktifkan via `PROFILE_ENABLED=True` (default aktif).
- Opsional: rekam video MP4 per transaksi via `PROFILE_VIDEO_ENABLED=True` (lebih berat; output di `transaction_logs/videos/`).

## Error Reporting via MQTT
Error fatal dari modul manapun dikirim ke MQTT topic DWS-SICEPAT/STATUS/ERROR sebelum proses exit, sehingga backend dapat mendeteksi dan menampilkan notifikasi ke operator.

## MQTT Payload

| Topic | Trigger | Isi |
| --- | --- | --- |
| DISPLAY/BARCODE | Tiap scan barcode / barcode di-clear | \{ barcode: str \} (string kosong = cleared) |
| DISPLAY/BARCODE | Antrian penuh | \{ status: "QUEUE\_FULL", barcode, reason \} |
| DISPLAY/MEASUREMENT | Tiap frame (~15fps) | \{ weight, length, width, height, volumetric, divisor \} |
| DATA/RESULT | Saat transaksi selesai | \{ barcode, weight, length, width, height, volumetric, divisor, image\_base64 \} |
| STATUS | Connect / disconnect | \{ status: "ONLINE" \} atau \{ status: "OFFLINE", reason \} |
| STATUS/ERROR | Error fatal | \{ status: "ERROR", failed\_module, error\_message \} |
| NOTIFICATION | Kalibrasi titik nol lantai | \{ status, title, message \} — title: CALIBRATING / PLATFORM\_OCCUPIED / OK / DEGRADED |

:::note

Topic dipublish dengan prefix `DWS-SICEPAT/` (mis. `DWS-SICEPAT/DATA/RESULT`). `image_base64` pada `DATA/RESULT` diambil dari kamera RGB sekunder jika tersedia. Saat MQTT reconnect, sistem mem-publish `STATUS/ERROR` kosong (retained) untuk membersihkan error lama. Format lengkap tiap payload ada di [MQTT payloads](https://github.com/PT-Ravelware-Technology-Indonesia/dws-sicepat-middleware-ai/blob/main/docs/mqtt-payloads.md).

:::

# Keputusan Teknis

| Keputusan | Alasan |
| --- | --- |
| Lantai dimodelkan sebagai **bidang 3D (RANSAC)**, bukan satu nilai jarak | Pemasangan kamera hampir tidak pernah benar-benar tegak lurus. Dengan bidang, kemiringan terkompensasi dan tinggi dihitung per piksel terhadap lantai. |
| L/W diukur di **ruang metrik**, bukan piksel | Ukuran piksel bergantung jarak ke kamera. Deproject ke mm membuat paket tinggi dan rendah diukur dengan skala yang sama. |
| Kalibrasi titik nol memakai **guard terhadap nilai terakhir yang valid** | Kalibrasi berjalan otomatis setiap restart, sering tanpa ada yang melihat. Tanpa guard, barang di platform saat restart bisa terkunci sebagai "lantai" dan membuat semua tinggi salah. |
| Knob pengukuran dibundel dalam **measurement profile** | A/B dan rollback cukup satu nilai, dan tidak ada knob sisa eksperimen yang ikut terbawa diam-diam. |
| `topface_legacy` tetap jadi **default**, filter depth **default mati** | Jalur point cloud dan filter depth butuh validasi di site dulu. Filter SDK juga bisa crash di level native, jadi harus dinyalakan dengan kamera terpasang dan diawasi. |
| Scanner handheld lewat **keyboard hook + TCP client** | Receiver hanya mode keyboard. Mengirim lewat TCP membuat listener memakai pipeline barcode yang sama dengan scanner TCP tanpa mengubah server. |

| mount\_height\_mm | auto/configurable | Jarak kamera ke lantai (mm). Dikalibrasi otomatis saat startup. |
| min\_height\_thresh | 50 | Tinggi minimum objek agar terdeteksi (mm). |
| erosion\_size | ikut profil | Ukuran kernel erosion untuk filter tepi depth (pixel, harus ganjil). |
| erosion\_iterations | ikut profil | Jumlah iterasi erosion. Semakin besar = contour semakin menyusut. |
| volumetric\_divisor | 6000 | Pembagi volumetric weight. Standar internasional 6000, udara 5000. |
| stability\_delay | 2.0 | Durasi kondisi harus terpenuhi sebelum trigger (detik). |
| barcode\_timeout | 15.0 | Barcode dianggap expired setelah N detik tanpa trigger (detik). |
| barcode\_debounce | 1.0 | Jeda minimum antara dua scan barcode yang sama (detik). |
| max\_match\_dist | 50.0 | Jarak maksimum centroid antar frame untuk tracking objek (pixel). |
| slope\_l | 1.0 | Slope regresi sisi panjang (L). `final = slope_l × raw + intercept_l`. |
| intercept\_l | 0.0 | Intercept regresi sisi panjang (L) dalam cm. |
| slope\_w | 1.0 | Slope regresi sisi pendek (W). |
| intercept\_w | 0.0 | Intercept regresi sisi pendek (W) dalam cm. |
| slope\_h | 1.0 | Slope regresi tinggi (H). |
| intercept\_h | 0.0 | Intercept regresi tinggi (H) dalam cm. |
| edge\_gradient\_threshold | ikut profil | Threshold Sobel (mm/px) untuk membuang piksel tepi depth yang tidak reliabel. `0` = nonaktif. |
